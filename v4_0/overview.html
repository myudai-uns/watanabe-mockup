全体像 — 1つの受注が最後までつながる

キックオフ共通方針「一度入力したデータは他帳票へ自動反映（二重三重入力を排除）」に基づき、v4.0の帳票はすべて受注データから自動生成します。現行の「帳簿と納品書・請求書がほぼ同じ内容の二重記入」（4/21議事録 4-5）を解消するのが最大の目的です。

受注（v3）→ 納品 ＝ 納品書 自動作成→ 帳簿へ自動記帳→ 請求書（月締め／個別）→ 入金 → 領収書

紙運用のメリット（クリアファイル回覧・手渡し）を残すため、各帳票はすべて印刷／PDF出力に対応します（4/21議事録 5-2 UI方針）。

1. 帳簿作成・編集 Phase 3 (5.6)

役割

売上帳への記帳を行う画面 — ただし原則は自動です。受注が「納品済み」になった瞬間にシステムが売上を記帳するため、日常業務で渡辺様が帳簿を「書く」作業はなくなります。この画面を使うのは例外時のみです。

  • 手動追加: 受注管理を通らない売上（店頭の現金即売など）を直接1行追加
  • 編集: 自動記帳された行の金額訂正・品目メモ（使用紙・インク等の仕様メモ）の補記
  • 反映範囲の選択: 修正時に「帳簿のみ直す」か「受注データごと直す（納品書・請求書にも反映）」かを選択 — キックオフ決定事項「変更時は反映範囲を選択式」に対応
議事録根拠: 4-4「記録項目: 日付、会社・個人名、品目、数量、金額、使用紙・インクなどの仕様メモ」／5-1「一度入力したデータは他帳票へ自動反映」「変更時は反映範囲を選択式（帳簿のみ／全体 等）」

記帳項目（1行あたり）

納品日／受注No／顧客（会社・個人名）／品目／数量／税抜・消費税・税込／区分（掛・現金）／回収状況／仕様メモ

2. 帳簿一覧 Phase 3 (5.6・5.7)

役割

記帳された売上を「月別」「顧客別」「地域別」に見る画面。現状「1年分が紙ファイルで蓄積し、年次決算時に参照するのが大変」（4/21議事録）を置き換え、2026年8月末の決算から使える集計を目指します。

主なビュー

  • 月別売上帳: 対象月を選ぶと納品ベースの売上一覧＋月計（税抜・消費税・税込）。当月売上・掛/現金内訳・未回収額のサマリー表示
  • 顧客別: お得意様は個別ページ（v3の顧客別履歴と連動。税抜累計・消費税累計・税込累計は5/27合意済みの項目）
  • 地域別: 亀谷・元町・東和・岩代・市街等での分類集計（正式な地域リストは先方共有待ち＝5/27対応事項No.11）
  • 売掛状況: 顧客ごとに「未請求」「請求済・未入金」を分けて表示（5.7 伝票・入金状況管理）
  • CSV出力: 決算・税理士提出用の書き出し（8.2 受注データのCSV出力の帳簿版）
議事録根拠: 4-4「お得意様は個別ページ、それ以外は地域別に分類」「過去発注の呼び出しが最重要用途」「年次決算時に参照するのが大変」／5-3 追加機能候補「月次／エリア別／案件別の売上・原価・粗利分析」

3. 納品書作成・編集 Phase 3 (5.3)

役割

現行の「手書き3枚複写（控／納品書／請求書）」の納品書部分を置き換えます。受注を「納品済み」にすると納品書が自動で下書き作成され、内容確認 → 印刷 → 現物に同梱、が基本動線です。書く作業は originally 帳簿と二重記入だったため、転記そのものを廃止します。

画面の動き

  • 品名・用紙・数量・単価・金額は受注明細から自動転記（編集は受注側で行い、納品書へ反映）
  • 備考欄のみ納品書上で自由編集
  • A4フォーマットに自社情報（社名・住所・TEL/FAX・適格請求書発行事業者 登録番号）を自動印字 — 印影・登録番号等は5/14議事録で「後日共有」→共有済みのものを使用
  • 「発行済にする」で発行記録（誰がいつ発行したか）を自動保存 → 時系列記録表へ
  • 印刷／PDF出力（3枚複写の「控」はシステム内に電子保存されるため不要に）
議事録根拠: 4-5「3枚複写（控／納品書／請求書）、手書き」「帳簿と記載内容がほぼ同じ → 二重記入になっている」／5.3「納品時に発行する納品書（PDF・印刷）」

4. 納品書一覧 Phase 3 (5.3・5.7)

役割

発行済み・未発行の納品書を一覧管理する画面。現行運用の「伝票有無（×は後から要発行）」チェックをそのままステータスとして再現します。

主な機能

  • 納品済み案件が自動で並ぶ（納品日順）。未発行＝赤表示で「×」の出し忘れを防止
  • 顧客名・期間・発行状況での絞り込み検索
  • 一覧から1クリックでプレビュー → 印刷 ／ 該当受注へジャンプ
議事録根拠: 4-5「『伝票有無（×は後から要発行）』のステータスもここで管理」／5.7「『伝票出した/未発行』のチェック」／5-3「未伝票…のリマインド」

5. 請求書作成・編集 Phase 3 (5.4)

役割

手書き3枚複写の請求書部分を置き換えます。作成方法は2通り（このうち月締めの運用詳細は要すり合わせ）。

  • 個別請求: 受注1件ごとに発行。納品と同時に請求する取引先向け
  • 月締め請求: 顧客と対象月を選ぶだけで、その月に納品した未請求分が自動で1枚に集約。掛のお得意様向け

画面の動き

  • 御請求金額（税込）を大きく表示、明細は納品日・品名・金額（受注データから自動転記）
  • 消費税欄は10%対象小計・消費税額を区分表示（インボイス対応）。登録番号・振込先（東邦銀行二本松支店ほか）・振込名義を自動印字 — 5/14議事録「振込先、振込名義は後日共有」→共有済み情報を使用
  • 値引き表示は見積書と同ルール（通常非表示・必要時のみ／名目は「値引き」「広告料名目」「自由記載」＝5/14合意）を踏襲予定
  • 「発行する」→ 発行日・支払期限を記録。「入金を記録」→ 入金消込、続けて領収書発行に進める
  • 印刷／PDF出力（将来: メール送付＝5.4記載）
議事録根拠: 4-5（現行3枚複写）／5.4「請求書の発行（PDF・印刷・メール送付）」／4-2 見積書の振込先・登録番号関連の合意を流用
要すり合わせ: どの顧客が月締めか（締め日・支払サイト）、個別請求との使い分けルール。現行の顧客ごとの請求慣行をヒアリングの上で確定します。

6. 請求書一覧 Phase 3 (5.4・5.7)

役割

請求書の状態（未発行 → 発行済 → 入金済）と支払期限を一覧管理し、「受取（金銭受領済みか）」の現行チェックを置き換えます。未入金の見落とし防止が主目的です。

主な機能

  • ステータス・顧客・期間での絞り込み。未入金は金額つきで強調表示
  • 支払期限超過の案件を赤表示（将来: Gmail・Googleカレンダー連携のリマインド＝キックオフ追加機能候補）
  • 入金記録はこの一覧からも実行可能。入金済にすると帳簿・時系列記録表へ自動反映
議事録根拠: 4-5「『受取（金銭受領済みか）』のステータスもここで管理」／5.7「『入金済/未入金』のチェック」／5-3「未伝票・未入金のリマインド（Gmail・Googleカレンダー連携）」

7. 時系列記録表 v4.0 新規提案

役割

1件の受注について「いつ受注し、いつ刷り、いつ納品し、いつ請求し、いつ入金されたか」を1本の時間軸で確認する画面です。各画面での操作が自動で記録されるため、手で記録する作業はありません。

主な機能

  • 一覧（マトリクス）: 全案件 × 「受注／納品／請求／入金／領収書」の日付一覧。止まっている工程は赤の「未」表示 —「あの仕事、請求まだだっけ？」に一目で回答
  • 詳細タイムライン: 行をクリックすると、その案件の受注 → 製作開始 → 完成 → 納品 → 納品書 → 請求書 → 入金 → 領収書を縦の時間軸で表示。次にやるべきこと（例:「請求書が未発行です」）を提示
  • 「未完了のみ表示」絞り込み／顧客・品名検索
関連する合意事項: 過去議事録に「時系列記録表」そのものの記載はありませんが、1.15「変更履歴の自動記録（いつ・誰が・何を）」、5/27ダッシュボード「直近の変更履歴」、5.7 伝票・入金状況管理、5-3「未伝票・未入金のリマインド」を1画面に統合する位置づけです。

8. 領収書作成・編集 Phase 3 (5.5・優先度最後)

役割

現行の「手書き2枚複写・現金手渡し時に発行」を置き換えます。キックオフで優先度は最後と合意済みのため、v4.0では最小構成です。

画面の動き（案）

  • 現金のお客様: 納品（＝現金受領）のタイミングで自動作成 → 印刷して手渡し
  • 振込のお客様: 請求書の入金記録時に「領収書も発行するか」を選択（希望時のみ）
  • 金額・宛名は自動転記。但し書きのみ編集可（例:「メニュー表印刷代として」）
  • 税抜・消費税の内訳を印字（インボイス対応）。5万円以上の現金受領時は収入印紙欄を自動表示、振込時は「印紙不要」注記
  • 2枚複写の「控」はシステム内保存で代替。発行履歴は一覧・時系列記録表から参照
議事録根拠: 4-3「手書き2枚複写、現金手渡し時に発行」「電子版なし」「優先度は最後」／5.5「現金支払い時の領収書発行」／5-3「PDF自動生成（将来的に領収書も）」

渡辺様への確認事項（次回打ち合わせ）

項目確認したいこと
請求の締め運用月締めのお客様はどこか。締め日（月末以外の有無）・支払サイト（翌月末等）
帳簿の分類地域別分類の正式リスト（5/27対応事項No.11の続き）。決算時に税理士へ渡す形式
納品書の運用納品書を付けない取引（口頭・常連）があるか。控えの紙保管を残すか
領収書発行タイミング（納品時自動でよいか）。但し書きの定型パターン
過去データ現行の紙帳簿をどこまで遡って取り込むか（機能要件8.5では直近1年分を想定）

動作イメージは v4.0 機能モック（v3に5画面を追加した状態）で確認できます。
